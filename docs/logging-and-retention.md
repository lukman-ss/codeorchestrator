# Logging & Retention Architecture

Coding Orchestrator provides a multi-tier observability and log retention subsystem designed to preserve diagnostic visibility while preventing disk exhaustion and credential leakage.

## Logging Layers

```
coding-orchestrator/
├── logs/
│   ├── application.log                  (Active Pino server log)
│   ├── YYYYMMDD-HHmm-NN-application.log.gz  (Archived rotated server logs)
│   └── tasks/
│       ├── <taskId>.log                 (Raw child process task stdout/stderr)
│       └── agent-<executionId>.log      (Worker/Auditor raw output)
```

1. **Application Server Log**: Structured JSON generated by Pino (`src/logger.js`). Records HTTP requests, routing events, database migrations, queue dispatching, and system shutdown sequences.
2. **Task Execution Logs**: Raw stdout and stderr emitted by OpenCode child processes, streamed and buffered in `logs/tasks/` via `TaskLogger`.
3. **Database Event Stream**: High-level structured lifecycle events stored in SQLite `task_events` for real-time WebSocket distribution and client replay.
4. **Systemd Journal**: Operational lifecycle logs managed by the host OS (`journalctl --user -u coding-orchestrator`).

---

## Automatic Redaction & Sanitization

To prevent sensitive tokens and confidential prompts from entering persistent log files, the Pino logger is configured with strict redaction paths (`src/logger.js`):

```javascript
redact: [
  'req.headers.authorization',
  'headers.authorization',
  'res.headers.authorization',
  'req.body.prompt',
  'error',
  'err',
  'message'
]
```

When an HTTP request or error object is logged, these fields are automatically replaced with `"[Redacted]"`.

---

## Log Rotation & Archival

Application server logs are rotated automatically via `pino-roll`:

- **Rotation Threshold**: When `application.log` reaches `LOG_MAX_SIZE` (default: `20M`) or at midnight daily.
- **Compression**: Rotated log archives are automatically compressed with Gzip (`.gz`).
- **File Limit**: Retains at most `LOG_MAX_FILES` (default: 10) archives. Older archives are purged automatically.

## Retention & Maintenance Policies

### 1. Task Execution Logs (`cleanupTaskLogs`)
- Runs every 24 hours via background interval (`src/services/task-logger.js`).
- Files in `logs/tasks/` with modification times older than `TASK_LOG_RETENTION_DAYS` (default: 7 days) are purged from disk.

### 2. SQLite Event History (`cleanupTaskEvents`)
- Evaluated every `CLEANUP_INTERVAL_HOURS` (default: 24 hours) via `src/services/maintenance.js`.
- Deletes rows from `task_events` belonging to terminal tasks (`completed`, `failed`, `cancelled`, `interrupted`) whose `finished_at` timestamp is older than `TASK_EVENT_RETENTION_DAYS` (default: 7 days).

### 3. Event Payload Truncation
- To protect SQLite from row bloating, any event payload exceeding `TASK_EVENT_MAX_BYTES` (64 KB) is truncated, storing a `payloadSnippet` and `_truncated: true` flag.
